# IBM Bob Prompt Playbook

Use these prompts exactly or adapt them slightly. The goal is to create strong evidence that IBM Bob was used meaningfully as a development partner.

## 1. Repository architecture

```txt
Analyze this repository as if you were onboarding a new developer. Explain the architecture, folder structure, main components, API routes, data flow, and how the demo works.
```

## 2. Developer onboarding

```txt
Generate a developer onboarding guide for this repository. Include setup steps, important files, development workflow, how to run the app locally, and where to add new features.
```

## 3. Documentation improvement

```txt
Review the README and documentation in this repository. Suggest improvements to make the project clearer for hackathon judges and future contributors.
```

## 4. Testing strategy

```txt
Suggest a practical testing strategy for this Next.js and TypeScript project. Include unit tests, integration tests, accessibility checks, and edge cases for the /api/analyze route.
```

## 5. Test generation

```txt
Generate example test cases for the main dashboard flow, the API request validation, loading state behavior, and error handling.
```

## 6. Refactoring review

```txt
Inspect the repository for maintainability improvements. Identify duplicated logic, unclear naming, component boundaries, type-safety gaps, and low-risk refactors.
```

## 7. Performance review

```txt
Review this Next.js app and suggest performance optimizations that are realistic for a hackathon prototype deployed on Vercel.
```

## 8. Accessibility review

```txt
Review the UI for accessibility improvements. Focus on keyboard navigation, semantic structure, color contrast, labels, and screen-reader friendliness.
```

## 9. Submission readiness

```txt
Review this repository against the IBM Bob hackathon requirements. Confirm what is ready, what is missing, and what I must add before submitting to lablab.ai.
```

## 10. Final report summary

```txt
Summarize how IBM Bob helped accelerate this project. Organize the summary by repository understanding, documentation, testing, refactoring, and developer productivity impact.
```

## Evidence tips

After each session:

1. Save Bob's relevant output in `docs/ibm-bob/session-notes/` or screenshots in `docs/ibm-bob/screenshots/`.
2. Commit changes generated with Bob.
3. Export the official Bob report and place it in `docs/ibm-bob/exports/`.
4. Mention the report path in the final lablab.ai submission.
