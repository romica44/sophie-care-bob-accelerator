# IBM Bob Task Plan

Use this sequence when IBM Bob access is enabled. Each task should be performed in Bob so the exported report shows real repository-context usage.

## Session 1 — Repository understanding

Goal: prove Bob can understand the full codebase and explain it to a new developer.

Expected output:
- Architecture explanation
- Folder-by-folder summary
- Main user flow
- Important components and API route description

## Session 2 — Developer onboarding

Goal: reduce ramp-up time for a developer who did not build this project.

Expected output:
- Onboarding guide
- Setup steps
- Common development tasks
- Where to add new features

## Session 3 — Documentation generation

Goal: generate or improve technical documentation for judges and future contributors.

Expected output:
- README improvement suggestions
- Architecture documentation
- Demo guide improvements
- Submission checklist review

## Session 4 — Testing strategy

Goal: use Bob to identify tests that would improve confidence.

Expected output:
- Unit test suggestions
- Integration test suggestions
- Accessibility test ideas
- Edge cases for API route and UI states

## Session 5 — Refactoring and maintainability

Goal: ask Bob to inspect the project and propose safe improvements.

Expected output:
- Duplicated logic analysis
- Component boundary suggestions
- Naming improvements
- Type-safety improvements

## Session 6 — Final submission review

Goal: have Bob review the repo against hackathon requirements.

Expected output:
- Missing deliverables
- Final GitHub readiness checklist
- Vercel deployment sanity check
- Reminder to export Bob report
